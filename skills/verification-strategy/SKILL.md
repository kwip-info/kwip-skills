# Verification strategy

Read the current accepted gate, task scope and measured evidence before changing verification.
Record the work and finite check plan in the existing tracker. Keep a replacement runner a
candidate until its accounting, correctness, isolation and change-impact behavior are qualified.
Do not change release policy in the middle of a candidate merely because another approach is faster.

Measure the actual cost: compilation, collection/imports, repeated discovery, child launch,
training, serialization/capture, assertions, intentional waits and cleanup. Preserve a canonical
case inventory with outcomes and source/helper ownership. Report what the stopwatch includes;
preflight and postchecks cannot disappear from an end-to-end budget by starting the clock later.

Set explicit fresh-qualification and localized-feedback budgets with host, toolchain, fixtures,
devices, dependency/cache conditions and baseline. Keep correctness and elapsed-budget verdicts
separate. Neither core-count division nor cached component results proves the fresh full target.

Use one disjoint union for complete and required-feature views. Required real-model cases execute
once per qualification and remain mandatory in a selected subset. Refuse missing, duplicate,
foreign, unfinished or unexpectedly skipped cases. Parameter display IDs may contain data; retain
stable digests and code-owned locations instead of copying payloads into receipts.

Build once and run exact binaries where supported. Use one reviewed slot/memory/native-thread
budget across languages and children, with private files, databases, settings, caches and mutable
model/RNG state. Keep real GPU, global OS state, deadlines, RSS and responsiveness checks exclusive.
Do not infer device use from a test name. Unknown sources, changed helpers or missing declarations
must fail preflight, not silently become an omitted or successful serial tail.

Prove isolation and process ownership with actual negative controls: stale settings, changed
fixtures, order changes, missing lanes, signal/deadline behavior and PID reuse. An environment
variable is not proof of private native preferences or temp paths. State the limits of sampled
RSS/descendant monitoring rather than claiming exhaustive memory or process control.

Reprogram expensive families at production-used seams. Pure matrices should not bootstrap a
whole app/model per example; numerical tests still run the real functions against independent
oracles. Reuse privately copied immutable artifacts for read/tamper variants, not a mutable model
or old training receipt to claim a fresh training run. Preserve actual process/security witnesses.

For failure follow-up, retain the original identity, source, command and result. Repair the
affected contract and broaden only for demonstrated shared impact or unresolved risk. A truthful
combined closure is distinct from a new full PASS. Do not shorten a real stress deadline to speed
it up; give positive cold-start work an allowance appropriate to its intended operation.

Adopt component evidence reuse only after exact dependency/identity checks and a regression-to-fix
rehearsal validated against complete results. A contract, helper, fixture, runtime or unknown-source
change must widen/refuse appropriately. Source qualification, native acceptance, final extracted
payload equality, actual authenticated updates/fallback and public promotion remain separate gates.

Keep receipts bounded and filter raw child output before persistence. Retain case/resource/ownership
metadata and useful failure locations, not environment dumps, assertion payloads or full datasets.
Update working instructions only after the new process is actually adopted; do not document a
pilot as a proven full gate. Respect the user's hosted-runner, spend and publication constraints.
